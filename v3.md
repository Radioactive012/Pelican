## 1. What V3 WILL HAVE (Core Scope & Architecture)

### 1.1 The Product
Context Passport is a **self-improving, privacy-first browser memory** extension that runs seamlessly across the top three AI platforms:
1. **ChatGPT** (`chatgpt.com`)
2. **Claude** (`claude.ai`)
3. **Gemini Web** (`gemini.google.com`)

### 1.2 User Interface & Extension Architecture
- **One Compact Extension UI**: Built with TypeScript (`v3/src/`) and packaged into `v3/dist/`.
- **Side Panel Vault**:
  - Displays distilled memories categorized as **General** or **Sensitive**.
  - Shows supporting evidence excerpts (with sensitive details redacted).
  - Displays learned **Explanation Preferences** (with observation counts, chat counts, and locked status).
  - Allows direct user corrections to preferences (which locks wording and prevents automatic AI overwrites).
  - Provides memory actions: **Block** (exclude from retrieval), **Delete/Forget** (tombstones source so retried events don't recreate it).
  - Provides **Capture Toggle** (Capture is **OFF by default** and toggleable per site).
- **Universal Fallback Route**:
  - If any site updates its DOM structure and the automated composer injection fails, the side panel provides a one-click **"Copy Memory Block"** clipboard fallback so the user is never blocked.
- **Inline Memory Composer Replacement**:
  - "Use Memory" button injects relevant memories into the active chat prompt wrapped in distinct boundary markers (`<!-- CONTEXT_PASSPORT_START -->` ... `<!-- CONTEXT_PASSPORT_END -->`).
  - Idempotent: Clicking "Use Memory" multiple times never duplicates injected blocks.

### 1.3 Backend Architecture & Localhost Runtime
- **Strict Localhost Loopback**:
  - FastAPI server bound strictly to `127.0.0.1:8000` (`http://localhost:8000`).
  - No public binding (`0.0.0.0`), no Render, no Fly.io, no cloud hosting.
  - Manifest V3 permissions explicitly allow `http://127.0.0.1:8000/*` and `http://localhost:8000/*`.
- **Single Application Database**:
  - **MongoDB Atlas** stores both Mem0 vector memories (`memories` collection) and core application collections:
    - `observations`: Atomic evidence for style preference learning.
    - `preferences`: Promoted explanation preferences.
    - `dedup_events`: Hash table tracking processed messages to prevent duplicate ingest.
    - `forgotten_preferences`: Tombstones for preferences rejected by the user.
    - `forgotten_memory_sources`: Tombstones for user-deleted memories ensuring queued retries never re-ingest them.
- **Auth Provider**:
  - **Supabase Auth** is used **strictly for user sign-in and JWT verification**.
  - No dual-database synchronization: identity is extracted strictly from verified JWT claims (`sub` / `user_id`).
  - Tenant isolation is enforced in MongoDB Atlas `$vectorSearch` using `ScopedMongoDB` which places `payload.user_id` inside the search filter.

### 1.4 Model Routing Architecture (Steps 1–9 Mocked, Step 10 Live)
- **Primary Fact Extractor**: OpenRouter GLM 5.3 Flash (`openrouter/glm-5.3-flash`).
- **Fallback Fact Extractor**: Gemini 2.5 Flash Lite via OpenRouter (`google/gemini-2.5-flash-lite`), activated automatically upon 429 rate limit, 5xx server error, timeout, or schema parsing failure.
- **Embedder**: `openai/text-embedding-3-small` (1536 dimensions) via OpenRouter.
- **Validation Pass**: Feature-flagged Jev from TypeSafe AI (`ENABLE_JEV_VALIDATION=false` by default).
- **Zero Paid Calls Discipline**: Steps 1–9 use mock providers and synthetic embeddings. Real API keys are connected **only at Step 10** with hard spending caps ($1.00 max).

### 1.5 Narrow Learning Engine (Explanation Preferences)
- Context Passport does **not** make wild guesses about personality.
- It learns **exactly one thing automatically**: **how the user likes answers explained** (e.g., "Prefers concise bullet points with minimal preamble", "Prefers step-by-step code walkthroughs").
- **3-Observation / 2-Chat Promotion Gate**:
  - An explanation preference is promoted to active memory **only after 3 distinct observations across at least 2 distinct conversations**.
  - A user correction immediately locks the preference wording and marks it `locked: true`, taking precedence over all future automatic suggestions.

### 1.6 Three-Tier Privacy Firewall
1. `general`: Working preferences, programming languages, tools, high-level preferences. Automatically eligible for retrieval (up to 3 general memories injected).
2. `sensitive`: Personal details, health/medical notes, dietary restrictions, financial context.
   - **Two-phase approval**: Never injected automatically. Triggers an explicit user prompt: **"Allow once"** or **"Don't use"**.
3. `secret`: API keys, passwords, bearer tokens, private keys, authentication secrets.
   - **Defense-in-depth screening**: Screened in the browser extension *before* network transmission, and screened again on the backend.
   - Recognizable secrets are completely skipped and dropped. Never stored, never logged, never embedded.

## 2. What V3 WILL NOT HAVE (Strict Non-Goals)

To prevent scope creep and maintain absolute stability, the following are **explicitly out of scope**:

1. **NO Separate Dashboard Web App**:
   - There is NO separate React/Next.js dashboard web app. Everything is managed inside the Chrome extension side panel.
2. **NO MCP Servers or MCP Client Adapters**:
   - No Model Context Protocol servers, no JSON-RPC daemon bridges, no local desktop MCP hooks.
3. **NO Cursor or IDE Coding-Assistant Extensions**:
   - No Cursor plugins, no VS Code extensions, no IDE integrations.
4. **NO Extra Websites**:
   - Only ChatGPT, Claude, and Gemini web. No Perplexity, no Poe, no HuggingChat, no Copilot web.
5. **NO Public Cloud Backend**:
   - No Render, Railway, Fly.io, or AWS deployment. The backend is local-only (`127.0.0.1:8000`).
6. **NO Raw Transcript Retention**:
   - The backend never logs, stores, or persists raw conversation message bodies or assistant transcripts.
7. **NO Assistant Turn Capture**:
   - Assistant responses are never captured as user memories.
8. **NO Self-Referential Capture**:
   - Extension-inserted memory blocks (`<!-- CONTEXT_PASSPORT_START -->`) are never re-captured as new user facts.
9. **NO Silent Fallback Embeddings in Production**:
   - If an API key is missing or invalid in production mode, the server fails visibly with a clear error; it never creates fake embeddings or corrupts the vector space.
10. **NO Mixed Vector Collections**:
    - Gemini vectors (from older versions) and OpenAI vectors are never searched in the same query.
11. **NO Shortcut Deletions**:
    - Existing memories are never deleted during migrations; safe backups and rollbacks are maintained.

### Step 3 — Embeddings & Safe Migration
- **Status**: **PASSED** (Commit `7425544`)
- **What it did**: Implemented 1536-dimensional `text-embedding-3-small`, model tagging on all MongoDB records (`payload.embedding_model`), `backend/migration.py` with backup collection creation, idempotent reruns, and full rollback.
- **Where it broke / Fragile points**:
  - **The SimpleNamespace Bug**: Existing unit tests used `SimpleNamespace` mock settings lacking `embedding_model`, causing `AttributeError`. *Fix: Use safe `active_embedding_model` property with `getattr` fallbacks.*
  - **Missing Model Tag in Legacy Test Mocks**: Older tests constructed raw document dicts without `embedding_model`. If strict filtering ran unconditionally, legacy tests failed. *Fix: Model filtering is enforced when settings specify an active model, while unit mocks without model config are safely supported.*
  - **Atlas Index Lag (Recent Write Race)**: MongoDB Atlas Vector Search has an eventual-consistency indexing lag (up to seconds/minutes). If a memory was saved and immediately searched, Atlas would not return it. *Fix: Direct-query recent writes (<5 min) from the collection, apply in-memory cosine scoring, and merge with Atlas results.*
  - **Vector Space Mixing**: Searching a collection containing both Gemini vectors and OpenAI vectors produces nonsensical cosine similarities. *Fix: Vector search strictly rejects documents whose `embedding_model` does not match the active model.*

### Step 5 — Three-Site Capture Adapters
- **Status**: **PASSED** (Commit `bde4e68`)


- **What it did**: Finished ChatGPT, Claude, and Gemini site adapters, send detection (submit, Enter key without shift, send button clicks), conversation IDs, SPA navigation handling (`history.pushState` and `history.replaceState` interception), and per-site capture toggles (defaulting to OFF). - **Where it broke / Fragile points**:
  - **HTML Comments vs. DOM textContent**: When memory injection blocks use HTML comments (`<!-- CONTEXT_PASSPORT_START -->...<!-- CONTEXT_PASSPORT_END -->`), standard browser `Element.textContent` drops comment nodes. `stripExtensionInjectedContext` and `CaptureGate` were updated to support both bracketed marker blocks (`[Context Passport: Memory]...[/Context Passport]`) and comment markers, ensuring injected context is always cleanly stripped regardless of rendering mode.
  - **JSDOM Missing HTMLTextAreaElement / Element Globals**: In headless or isolated test environments, `HTMLTextAreaElement` or `HTMLInputElement` may not be in global scope. `readComposer` and `writeComposer` now check `typeof HTMLTextAreaElement !== 'undefined'` and fallback to tag name checks (`composer.tagName === 'TEXTAREA'`), preventing ReferenceErrors.
  - **TypeScript Type Stripping in Node 24 ESM**: Type-only interfaces like `CaptureIngestPayload` must be imported using `import type { CaptureIngestPayload }` so Node `--experimental-strip-types` does not fail on non-existent runtime value exports.
  - **SPA Navigation Without popstate**: `window.history.pushState` and `window.history.replaceState` in React/Next.js apps do not fire native `popstate` events. Intercepting `pushState` and `replaceState` in `observeRenderedUserMessages` ensures that SPA route transitions immediately trigger observer scans and conversation ID updates.
  - **Assistant Text & Nested Element Filtering**: ChatGPT, Claude, and Gemini adapters explicitly filter out `[data-message-author-role="assistant"]`, `[data-testid="assistant-message"]`, `.font-claude-message`, `[data-is-streaming="true"]`, `<model-response>`, `.model-response-container`, and `[data-sender="model"]`, and deduplicate nested user nodes (`!nodes.some(other => other !== node && other.contains(node))`), guaranteeing that only the outermost user turn produces an event.
  - **Per-Site Dynamic Toggle Fallback**: Chrome storage listener in `content/index.ts` safely guards against undefined `chrome.storage.onChanged` in non-extension or headless testing contexts.

### Step 6 — Recall, Consent & Injection
- **Status**: **PASSED (commit `42ba8c4`)**
- **Goal**: "Use Memory" button, auto-selecting up to 3 general memories, sensitive consent modal, composer replacement, and manual fallback UI.
- **What it did**:
  - Implemented `handleUseMemoryAction` orchestrator in `v3/src/core/recallController.ts` handling query extraction, top-3 general selection (`general.slice(0, 3)`), two-phase Privacy Firewall sensitive approval modal (`promptSensitiveApproval`), and idempotent memory block formatting (`formatMemoryBlock`).
  - Implemented defense-in-depth secret & sensitive screening (`screenRecall`) ensuring misclassified secrets are dropped completely and sensitive candidates are demoted to explicit approval.
  - Implemented in-flight draft race protection (`latestDraft !== cleanDraft`) preserving user edits typed while recall was resolving.
  - Built universal manual copy/paste fallback modal (`showComposerFallbackUI`) with automatic clipboard write (`navigator.clipboard.writeText`) when site composers cannot be controlled directly or DOM changes.
  - Connected extension content script (`v3/src/content/index.ts`) and styled fallback cards, toasts, and buttons (`v3/src/content/styles.css`).
  - Added comprehensive test suite `v3/tests/step6-recall.test.ts` (10 tests) covering all criteria, passing 100%.
- **Where it broke / Fragile points**:
  - **In-flight draft modifications**: If the user types or edits their prompt while the memory retrieval network call is resolving, unconditionally overwriting the composer would wipe out their newly typed text. *Defense: Controller records the initial draft, and re-checks the current draft upon recall completion; if changed, it preserves the latest draft and warns with `'Draft changed—retry'`.*
  - **Fast repeated clicks / UI locking**: Disabling the button without synchronous release upon action completion blocked immediate follow-up clicks or re-recall attempts. *Defense: `button.disabled = false` and `loading` class removal are invoked immediately on action completion, while temporary status labels ('Attached!', 'Copied to clipboard') revert after a non-blocking timeout.*
  - **Short Bearer tokens in screener**: Bearer tokens with fewer than 20 characters (such as test or internal token formats `Bearer my-secret-token`) bypassed length-20 regexes. *Defense: Tightened regex threshold to `{12,}` in `v3/src/core/screener.ts` to match generic API key length heuristics.*
  - **Node 24 JSDOM navigator.clipboard getter**: In Node 24 ESM tests, `globalThis.navigator` is a non-configurable getter. Mocking clipboard writes required `Object.defineProperty(globalThis.navigator, 'clipboard', ...)` instead of mutating `globalThis.navigator`.
  - **DOM text stripping and capture immunity**: Verified that newly inserted `[Context Passport: Memory]...[/Context Passport]` and `<!-- CONTEXT_PASSPORT_... -->` blocks are completely stripped before capture evaluation, ensuring injected context never counts as captured user evidence.
